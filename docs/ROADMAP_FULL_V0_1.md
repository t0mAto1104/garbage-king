# 两人开发路线图（长期产品）

> 预估依据：两人兼职，每人约 15–25 小时/周，Godot 已有 v1.1 基线。预估不是承诺，不包含已发生的开发周期。

## 1. 交付策略

**先验证现有 10 分钟 Can Stomper，再决定下一步开发完整人物版还是继续鞋光标工具版。** 不要重新从零开始。
阶段 A：1–2 周，改造成可验证的“鞋→锤→钻”灰盒玩法；阶段 B：3–8 周，总计约 20–30 分钟新产品切片；阶段 C：9–20 周，扩展 3–5 小时内容；阶段 D：21–24 周，质量、发布、宣发。如实际人力不足，应削减范围，不能一边增加内容一边维持承诺日期。

## 2. 角色分工

| 工作 | 开发者 A（偏技术） | 开发者 B（偏内容） |
| --- | --- | --- |
| 经济/攻击/状态/存档 | 主责 | 试玩、配置建议 |
| 传送门/工具/自动化 | 主责 | 动画、美术效果 |
| 主角/垃圾/场景像素 | 贴图集成 | 主责 |
| UI/菜单 | 交互与数据绑定 | 版式、图标 |
| 序章/剧情 | 状态与事件 | 文案、静态插画 |
| 音效/BGM | 引擎集成 | 采集、制作、许可记录 |
| 数值平衡 | 自动模拟 | 真人试玩与修改 |
| 发布/测试 | 性能、导出、回归 | 产品完整体验、宣传物料 |

一任务一负责人，范围写到 Issue 或 PR；不允许两个 AI 同时修改同一工作区；长期项目状态以 Git 版本文档为准。

## 3. 前八周具体交付

| 周 | 技术优先级 | 内容优先级 | 验收 |
| --- | --- | --- | --- |
| W1 | 基线测试、固定工具扩展点、保留旧场地 | 新产品镜头与输入对比稿 | v1.1 完整保留，新玩法实验有独立入口 |
| W2 | 新工具 CD/攻击抽象、锤击原型 | 锤子占位、碎裂 SFX | 鞋和锤在节奏/反馈上有区别 |
| W3 | 机械手购买与装备切换 | 主角半身像、锤子/电钻 | 用回收金首次改造 |
| W4 | 电钻高频攻击、音效/弹字限流 | 电钻循环动画、破损层 | 高频状态无重复收益 |
| W5 | T1 垃圾数据、材质规则、门深度 | 小电器 4–6 种、背景装饰 | 解锁出现新种类 |
| W6 | 轻自动化/一次特殊事件 | 事件反馈、BGM | 15–20 分钟闭环可玩 |
| W7 | 序章短剧情、图鉴、保存字段 | 插画、UI 一致化 | 从开局到切片结尾顺畅 |
| W8 | Bug、平衡、性能、导出 | 外部试玩、调整音画 | 可分享 Windows 测试包 |

只有当 W2 的工具差异、W4 的高频反馈、W6 的成长循环得到正面反馈，才推进大量后续内容。W1–W8 只是计划，暂未执行。

## 4. 20–30 分钟 Demo 范围

应有：开场简短/可跳过、初始踩罐、机械手、锤、钻、9 种左右垃圾、传送门 2–3 视觉等级、简单商品升级、1 次特殊事件、存档与设置、一个明确收尾目标。现有红蓝金罐可计入 9 种；不要同时引入稀有零件、转生、复杂机体构筑、五章节剧情和真实破裂。

建议节奏：
0:00 序章与第一罐；约 3–5 分钟机械手；8 分钟锤手；15 分钟电钻；19 分钟事件；25 分钟洗衣机/大型目标。所有时间为首轮目标，需真人试玩调整而非强制放货币。

## 5. 完整版范围与削减顺序

正式版上限建议：5 章节、约 30–40 个独立垃圾外观、7 个工具阶段、4–6 左臂模块、10–15 质变节点、40–60 数值升级、3 种事件、5 种背景阶段、5–7 首 BGM。
时间超出时优先削减：额外 NPC 对话 → 非关键美术差分 → 多余垃圾外观 → 左臂模块 → 第五章大件演出。始终保留“玩法上不一样的工具”和各阶段可见成长。

**首版不做**：多人、开放探索、真实物理切割、战斗、多库存经济、强制转生、复杂主角行走、Steam 成就系统集成（可晚些再看）。

## 6. 退出条件（交付关口）

- A：第一分钟获得反馈、脚踩/锤子可玩、原有存档与罐堆逻辑回归测试不退化；
- B：至少 5 位非开发者完整试玩，前 5 分钟能理解目标，20–30 分钟形成新升级高潮，反馈与留存问题被记录；
- C：3–5 小时内容测试时无十分钟以上没有决策的空窗；每章都有至少一个能力质变；
- D：正式导出、商店截图、许可台账、多人测试清单、崩溃/坏档处置、最终价格验证。

不要用“模拟器通关时间”冒充真实玩家；不要以旧 Windows 包的资源探针当作新版本真机测试。
