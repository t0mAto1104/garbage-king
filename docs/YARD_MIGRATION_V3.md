# 工坊切片：配置与存档迁移设计

决策依据：2026-11-01 人类明确要求按新 GDD 继续开发、融合踩罐原型、采用轻像素风与 2K。
跟踪：GitHub Issue #2，分支 `feat/codex-recycling-yard`。此设计作为独立提交，随后提交实现和迁移测试。

## 入口与数据边界

- 新默认入口 `scenes/yard.tscn`；经典参考入口仍为 `scenes/main.tscn`。
- 原型 `data/demo_balance.json` 不变；新工坊唯一数值源为 `data/yard_balance.json`，配置 schema=1。
- 新配置扩展为 trash/tools/upgrades/events/chapters，加载器验证目录 ID、价格、间隔、材质、工具专属参数与前置。
- 新目录保留 red/blue/gold 稳定 ID 与旧 HP=3/5/8，使旧场地可直接校验。
- 扩展 `StompCanField` 的可选 `shape_scale`，默认 1，不改变原始三罐状态；场地和序列号机制继续复用。

## 两条存档路径

| 内容 | 路径 | 内容版本 |
| --- | --- | --- |
| 经典 Demo | `user://save_v1.json` | v1/v2 兼容，现存完整场地为 v2 |
| 新工坊 | `user://yard_save_v3.json` | v3 |

Godot 的应用配置名保持不变，避免迁移时改变 user:// 根目录。窗口标题单独显示“垃圾王 · 传送工坊”。

首次打开新工坊：有 v3 就验证读取 v3；没有 v3 才尝试读取经典存档。
旧 v1/v2 先经过原型状态加载器验证，再映射金币、累计收入、计数、完整场地与相关升级。
blue_can → depth I；gold_can → quality I；自动线与供罐等级保留。
新增工具默认仍从鞋开始，不凭空赠送已购买义肢；重走改造是新内容。

导入不修改旧文件。后续只写新 v3，写入采用临时文件+原子重命名。
两个模式此后各自保存，切换模式不反复合并钱或物品，避免重复导入收益。
恢复时不补离线垃圾/金币；自动线未完成周期从零开始，与原型规则一致。

## v3 新增状态

工具所有权/装备、传送深度与品质、扫描/磁力、发现/回收图鉴、狂拆能量及剩余时间、
事件种类/剩余时间/下次触发点、章节完成标志、故事与音频设置。
废品堆仍保存位置、运动、旋转、HP、已结算标志、供货周期；大型物件额外保存 shape_scale。

坏档/不兼容数据：先保留 `.corrupt-backup`，界面报告，再用新状态开局；不删除或覆盖原始经典存档。
备份失败必须如实提示，不能宣称备份成功。新存档损坏时不自动再次导入旧钱包。

## 契约和测试

- 新 `YardState.attack(serial, point)` 与 `hit(item,payout,damage,weak)`，不替换旧 `StompState.stomp`/`hit(can,payout)`。
- 命中判定使用 logical 1280×720 世界坐标；2K UI 将输入除以 2，Godot 窗口按比例缩放。
- 扩展物件大小时，同时扩展命中与软接触；不可只放大图像。
- 验证 v1 经济导入、v2 堆积/部分损伤映射、v3 读写、工具所有权、坏数据原子拒绝、
  旧文件字节不变、坏档源与备份保留、恢复不重复发奖。
- 无法用当前 Mac 环境证明 Windows 实机或长期真人体验；这些继续列为待验证。

## 恢复

新模式出问题时可从“经典 Demo”继续原存档，或用已记录的 Git 提交恢复旧入口。
不要删除玩家的 v2/v3 文件；回退代码不会自动反向合并新模式进度。
