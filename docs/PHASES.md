# Codex 开发任务 Phase 0–7（阶段验收）

## P0 工程骨架
建立 Godot 4.7.2 Standard GDScript 工程，project.godot，1280×720，2D像素最近邻导入设置，主场景、UI层、可用资产引用、data loader、状态及日志。显示左栏、车库、当前红罐、静态鞋子鼠标（只有交互区有效）。
**验收：** 能打开游戏；不会出现缺失脚本、资源和输入错误；光标在游戏区与UI区正确切换。

## P1 踩踏手感（最高优先级）
移动鼠标鞋指针，悬停触发每0.68秒一次踩踏，左键/空格兜底；CD防重入；主罐HP3、5状态变形、Shake/Particles/金币反馈、0.85秒换罐。可先显示金币但不做商店。
**验收：** 初始红罐必需3脚压扁（脚力1），不通过时不结算，完成时只加6金；UI点击不触发踩罐；离开碰撞停止踩踏。重点人工评价“是否爽”。

## P2 数据与成长
引入`data/demo_balance.json`，数据驱动罐、升级与概率；三类基础升级，购物流程，锁定条目解锁条件提示。
**验收：** 脚力1时红罐2脚、脚力2时1脚；回收溢价每级加算30%；金币不能负，满级不能再买；价格正确更新。

## P3 解锁新罐与概率池
累计踩扁条件 + 一次性解锁成本，蓝罐、稀有金罐生成池；稀有视觉表现更明显。不同罐HP和金币值由JSON控制。
**验收：** 未解锁不能生成；允许解锁后概率出现；概率检验N=10000在统计允许范围；发奖励一次。

## P4 独立自动踩踏机
左侧 Automation 购买按钮、右上角小传送带/自动设备、机器计时条；自动线每4秒压扁一只普通红罐，加币/数量；离开主罐也运行。
**验收：** 机器在UI交互和鼠标停留空白时独立运行；暂停时暂停；重新开始不会残留多个timer；手动罐HP不被机器更改。

## P5 设备升级与生产线外观
增加Auto Speed和Conveyor，0.75x间隔加成与清晰视觉区分。设备动画不靠实体物理大量实例化；可复用节点。
**验收：** 收益计算基于自动完成次数，不因变更动画而重复；两项升级不破坏当前正在进行的设备进度；主角玩法仍然可操作。

## P6 存档、教学、音频、试玩总结
持久存档、暂停、重新开始确认、首次教学、背景音乐/音效（占位也可）、特效减弱开关、600秒试玩总结。
**验收：** 关闭重新打开保留资源等级；无离线收入；总结可以关闭继续玩；旧/坏档可恢复；每次按停止/重开时没有额外奖励。

## P7 整合验收和导出
完成引擎内测试、经济模拟回归、玩家10分钟实测、视觉素材优化，导出目标桌面可运行版本（能导出哪个平台就报告哪个；不要假设已安装出口模板）。编写README_RUN.md、BUGS.md、CHANGELOG.md，输出测试记录。
**验收：** 所有关键操作可完成。若无Godot可执行文件，则未进行真实Godot测试，必须明确告知而不是宣称通过。

## 每阶段交付报告模板
