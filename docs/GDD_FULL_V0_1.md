# 《垃圾王 / 废品飞升》完整产品 GDD v0.1

> 文档状态：**长期产品设计提案（未实现）**。已有可玩原型为 Can Stomper v1.1；当前实际规则请先读 AGENTS.md 和 docs/PROJECT_STATE.md，不要把本文直接当成已经实现的功能，也不要擅自推翻鼠标鞋尖、持续供罐、多罐堆积、独立自动线和存档 v2。
>
> 设计日期：2026-10-31。团队：2 人。平台设想：Windows PC、Godot 4.7.2、GDScript、纯 2D。

## 1. 一句话定位与体验支柱

一名因救恋人受伤而失去双臂、又经历感情破裂的年轻人，意外获得跨维度垃圾传送门，从用脚回收易拉罐开始，用赚到的钱安装机械义肢、升级回收厂与传送门，最终能够拆解异界巨型废弃科技。

四个核心回报：
1. **操作反馈**：脚踩、锤击、钻孔、冲压、切割的音画与节奏明显不同；
2. **视觉成长**：从破棚与旧鞋，到机械义肢、流水线、空间设备；
3. **经济增长**：回收收益与拆解能力同步快速增长；
4. **探索与反差**：门里出现越来越离谱的废品，每章首次出现新类别都构成奖励。

产品形态：主动拆解 + 增量升级 + 逐步自动化 + 轻度工具构筑；固定单屏主舞台，鼠标优先，无战斗和自由地图。首轮完整版目标 3–5 小时，先用 20–30 分钟的独立切片验证玩法；**均为目标，不是已验证成绩**。

## 2. 正在运行的原型 vs 长期叙事

当前项目已存在 Can Stomper v1.1：鼠标是鞋，鞋尖判定；车库左侧升级栏、右侧场地；持续供罐且未踩罐堆积；红蓝金各五帧；独立自动回收线；经济从 data/demo_balance.json 读取；存档 v2 保存场地状态；600 秒后总结但仍可继续。这些作为可复用的初期踩罐原型保留。

本文件设想增加的**可见主角、机械义肢、右侧快捷升级区、单个平台一件垃圾、主动锤手/电钻**，与现有实现有交互冲突。未经另一次明确设计决策，不重做 v1.1。优先比较两种兼容方案：
- **路径 A（低风险）**：继续以鼠标工具作为操作光标；叙事与改造界面展示主角、义肢，场内工具光标逐阶段由鞋变机械手/锤/钻。保留持续供罐、堆积、左侧升级栏。
- **路径 B（高成本）**：出现完整侧视主角、固定拆解平台、角色攻击动画；需要改主场景、输入与表现、垃圾动态、旧存档兼容，并单独估算。
建议先验证 A，再决定是否需要 B 的演出价值。

## 3. 故事基调与序章

气质建议：40% 底层逆袭、30% 荒诞黑色幽默、20% 科幻谜团、10% 情感转变。主角的残疾和截肢不是笑点；幽默来自离谱的商业环境、奇怪的废弃物、系统吐槽。剧情不以羞辱女性或残疾为卖点。终局强调主体性，而不是凭财富获得前任认可。

序章目标 45–60 秒，可跳过，使用静态像素插画 + 文字：
1. 雨夜事故，主角救下恋人，双臂严重受伤后截肢。
2. 在医院获知恋人离开，主角生活陷入困境。
3. 搬入破旧仓库，发现不明设备；系统“小破”宣布“跨维度废弃物转运系统启动”。
4. 第一只罐子落下，显示“预计回收价值：6 元”。
5. 主角说“六块钱也是钱”，操作权交给玩家。

主要 NPC（优先头像 + 文本，无需完整行动 AI）：
- 主角：名字可自定，身体与资产可视化成长；
- 小破：传送门 AI，教程、吐槽、事件播报；
- 老周：废品商，解释回收市场；
- 林医生：义肢技师，改造界面；
- 前任：序章背景与结局收束，减少戏份；
- 回收集团经理：中后期竞争与商业阻碍。

## 4. 章节结构（建议）

| 章 | 情绪/主线 | 玩法变化 | 代表性终点 |
| --- | --- | --- | --- |
| I 破罐子破摔 | 求生、第一次赚到钱 | 脚踩、基础货币、第一只机械手 | 能处理小电器 |
| II 钢铁双手 | 义肢改造 | 锤手、电钻、材质差异、弱点 | 拆大型家电 |
| III 垃圾大王 | 小厂创业 | 自动化、第二攻击/辅助槽、多件处理 | 自动作业流水线 |
| IV 工业怪物 | 工厂扩张与竞争 | 液压、工业垃圾、群体连锁 | 工业机床/汽车残骸 |
| V 万界回收王 | 传送门来源揭晓 | 等离子、引力、异界废品 | 拆空间站核心，收束主线 |

每章应出现一个“第一次”：第一次使用机械手、第一次快速钻透、第一次同时拆三件、第一次拆汽车残骸、第一次拆异界核心。剧情共约 6–8 个关键节点、8–12 分钟阅读内容，日常升级用一句吐槽，不中断操作。以上章节尚未制作。

## 5. 核心循环

传送门送垃圾 → 玩家用当前工具命中 → 可见变形/破损 → 首次耐久清零时结算回收金和可选零件 → 买义肢/传送门/自动化 → 更快回收更高价值目标 → 再循环。

控制原则：允许长按鼠标/悬停自动连续动作，避免点击疲劳；主动操作价值来自目标、弱点、工具策略而不是拼手速；UI 操作时独立自动线继续运行。当前已实现的“鞋尖悬停共享冷却、按空格兜底”必须在产品重构前继续保持。

### 5.1 拆解反馈
- 每件垃圾配置 ID、名称、Tier、HP、基础售价、材质、尺寸、品质、词条、掉落表和美术引用。
- 建议视觉状态：100–66% 基本完整；66–33% 轻裂纹/凹陷；33–1% 重破损；0% 破裂/金币。实际 Can Stomper 已有五帧易拉罐，优先沿用，不回退。
- 命中音效、物体平移/抖动、火花或碎屑、伤害弹字；击毁时少量金币粒子，**经济只触发一次**。
- 物体不做真实逐像素断裂和大量物理刚体，优先序列帧、裂纹遮罩、碎片对象池、有限震屏。
- 高频电钻/激光不逐次震屏、停帧或产生单独 UI 字体对象；使用节流和合并数值。

### 5.2 伤害差异与主动性
四材质建议：轻质/脆性、普通金属、厚重机械、高级复合。相性：擅长 ×1.5，不擅长 ×0.75，其余 ×1。弱点暂定命中 ×1.5。首版只有单个可选弱点区域，不做多部件物理拆卸。材质与弱点在正式产品切片验证前都**不加入现有罐数据**。

### 5.3 狂拆爆发（可选）
每次击毁增加 10 能量，弱点击毁 +5，3 秒内连击 +5；达到 100 进入 8 秒狂拆：攻击频率 +50%、供货 +30%、音乐加层。结束清空计量，爆发期间不无限回充。前期 Demo 可用一次固定事件验证，性能与防闪烁优先；此机制目前没有实现。

## 6. 角色与义肢

角色成长最重要的差异点：从双脚到义肢再到超规格机械工具；每项重大解锁都要有外形改变与玩法质变。建议右臂主动攻击、左臂辅助构筑，避免两只手都做完整动作的额外成本。

| 阶段 | 工具 | 解锁价（提案） | 基础能力（提案） | 玩法辨识度 |
| --- | --- | ---: | --- | --- |
| 0 | 脚踩 | 免费 | 1 伤 / 0.55 秒 | 开局反差 |
| 1 | 基础机械手 | 160 | 3 伤 / 0.40 秒 | 第一次握拳 |
| 2 | 动力锤手 | 600 | 10 伤 / 0.75 秒 | 重击/震荡 |
| 3 | 高速电钻手 | 2,000 | 4 伤 / 0.12 秒 | 高频持续攻击 |
| 4 | 液压冲压臂 | ~20,000 | 60 伤 / 0.70 秒 | 范围冲击 |
| 5 | 等离子切割臂 | ~200,000 | 25 伤 / 0.08 秒 | 穿透切割 |
| 6 | 引力粉碎义肢 | ~3,000,000 | 待标定 | 多目标吸附 |

**重要：以上数值不是现有 JSON 的运行时参数。现有脚踩 CD 为 0.68 秒，绝不能被本文 0.55 秒覆盖。**

质变节点举例：双重出拳、锤击震荡波、电钻穿甲、连续钻孔伤害逐步加成（上限 ×2）、液压击毁追击、激光折射、引力吸附。数值强化与质变强化分层，普通强化可采用 ceil(C0×1.25^n)，价格/上限仍需模拟与试玩。

左臂辅助设想：磁力收集、弱点扫描、材料分析、被动夹具。Demo 原则上不做复杂左右手操作，仅预留 UI 概念。

义肢改造所：半身/全身角色预览、左右槽、装备统计、升级花费、安装反馈。首次手臂安装播放 5–8 秒机械装配特写（可以跳过）；不表现血腥手术。

## 7. 传送门

它控制“速率、品质、空间深度”，每次重大解锁要出现新物体。
- 速率：加快供货，后期可并发处理多个目标；
- 品质：稀有废品机会、价格倍率；
- 深度：从生活垃圾到电器、电子、工业、异界。
外观阶段：破损门框 → 稳定金属环 → 双环 → 工业门 → 空间裂缝。门的视觉阶段与数值等级分离，避免每一级都绘新图。
事件提案：垃圾暴雨（短时间高供货）、黄金回收日（收益倍率）、异界错误包裹（跨级特殊掉落）。

当前原型并非“单件清空后再生成”，而是按独立传送带计时持续供罐，未完成目标堆积。长期版本如果采用多件处理，应该从此结构演化；不可因为旧纸面方案就修改已认可的持续供罐体验。

## 8. 自动化、货币与长期成长

主要货币“回收金”，击毁后自动结算，不要求手动售卖。第三章可以引入第二资源“稀有零件”，用于质变模块；不做铜、铁、塑料等多库存。
- 初期：自动生成垃圾、自动结算；主动踩/拆；
- 中期：独立自动线，在 UI 操作时持续产币；
- 后期：智能回收、多目标与偏好选择。
- 未来可考虑离线收入：解锁自动线后，最多 2 小时按理论收入的 25% 结算，不触发稀有掉落。**当前 v1.1 明确无离线收益，不修改这一点。**
- 不加入强制转生：重置身体/义肢可能破坏故事成长；可考虑通关后可选“传送门校准周目”，保留角色和叙事进度。

## 9. UI 与玩家信息

当前原型保留：1280×720、左侧约 24% 升级面板、右侧场地、鞋子光标、持续堆积；正常光标在 UI 上可精确购买。
长期可讨论：顶部资金/每秒收入/工具 DPS/门等级；左侧升级卡；底部导航至义肢、传送门、工厂、图鉴、设置。此前提出的“右侧快捷升级面板”与当前左栏布局冲突，暂不作为执行要求。
UI 关注已购等级、花费、当前能力、解锁门槛；不要常驻过多解释文本，详情放帮助面板。设置含静音、效果降级、暂停、确认重置。

## 10. 目标体验与成功标准

首个 20–30 分钟产品切片（**与已经完成的 10 分钟 Can Stomper 原型不同**）的设计目标：
- 0–1 分钟：踩罐与收益；
- 1–3 分钟：小升级；
- 3–5 分钟：第一次机械手改造（新内容）；
- 5–8 分钟：小电器与锤手；
- 8–15 分钟：弱点/连锁与电钻；
- 15–20 分钟：传送门事件或自动化；
- 20–30 分钟：大型家电/章节结算。

验证：试玩玩家能在无讲解时理解核心循环；能够准确描述不同工具的手感区别；安装义肢引发可感知的奖励；没有长时间被迫等待。时间节点只作为调参目标，不硬编码强制进度。

## 11. 明确非目标

不做开放世界、自由探索、多人、复杂战斗、真实软体物理、大量库存、随机装备洗练、服务器、移动端同步开发、强制重置、付费加速。正式版与 Demo 分开排期，未经验证不提前制作全套大物体美术。
