# 10分钟增长曲线模拟与调参建议

模拟脚本 `tools/simulate_balance.py` 是**理想化数值推演，不是 Godot 实际运行/真人试玩**。

统一初值：金币0、普通罐3耐久/6金币、0.68秒踩踏间隔、0.85秒生成间隔、脚力1伤害。玩家在浏览升级栏时鼠标离开罐子，所以模拟以 `duty` 代表有效操作比例；例如 `.40` 意味着仅40%的平均时间积极操作。模拟含简化购买优先级策略；真实操作与经济结果可发生较大变化。

`python tools/simulate_balance.py --duty 0.40` 参考输出（seed 7）：
- 0.23 分钟：脚力升级1（减少红罐需要脚数）
- 0.69 分钟：金币价值升级1
- 1.44 分钟：蓝罐解锁
- 3.40 分钟：金罐解锁
- 5.50 分钟：自动踩踏机解锁
- 7.00 分钟：自动踩踏机效率升级
- 9.40 分钟：传送带解锁

不是所有玩家都按这些顺序。没有硬定时门槛，购买和升级必须在资源充足、前置满足时立即可用。

## 调参优先级
1. 玩家在前10秒是否能理解、前30秒有无第一个升级。
2. 单罐压扁时间与反馈是否有持续手感；避免持续“空罐替换等待”。
3. 稀有罐给予明显但不过度的奖励刺激；首个稀有罐出现不能保证随机次数，必要时后续可加入新手保底，但**首版不擅自开发**。
4. 自动机必须明显改善被动增长（尤其玩家在UI菜单查看升级时）。
5. 如果所有内容4分钟内达成，先提高自动设备成本/门槛而非延迟鼠标交互；如果10分钟几乎无自动机，则优先降低自动机成本或补发价值升级。

## 测试方式
- `python tools/test_balance.py`
- `python tools/simulate_balance.py --duty 0.40`
- `python tools/simulate_balance.py --duty 0.55`
- 再从真人试玩录屏记录实际节点。
