# 长期产品决策记录 / 待定事项 v0.1

此文件严格区分实际生产事实、团队提出的产品构想和未经测试的建议。任何工作开始前先读 AGENTS.md、docs/PROJECT_STATE.md；优先使用真正的代码和测试确定“已经实现”。

## A. 已确认的事实

- 仓库和项目名称：垃圾王（garbage-king），私有 GitHub 仓库，两人协作。
- Godot 4.7.2 + GDScript + 2D；已经有 Can Stomper v1.1 可玩原型、三种罐五帧、实时持续供罐、多罐堆积、鞋尖光标和独立自动回收线。
- 现有传送间隔、经济和升级参数以 data/demo_balance.json 为权威来源，现有存档 schema v2，无离线收益。
- 长期创意方向已由团队明确选择：**废品拆解增量游戏 + 传送门 + 义肢成长 + 底层逆袭**。
- 本次工作范围为**整理和发布文档**，不是直接实施新玩法，也不是更改旧存档、发布包或游戏代码。

## B. 产品设计偏好（已讨论，尚未转运行时）

- 世界观：救恋人而失去双臂，之后分手，落魄的主角捡到垃圾传送门，从踩罐开始建立回收事业；
- 主角后续安装机械手、锤手、电钻等，工具不止数值增加，还改变打击方式；
- 传送门逐步解锁更高价值、范围更广的废品；
- 一次性 PC 买断游戏为初步商业化方向；
- 五章节、3–5 小时完整版、20–30 分钟切片为目标规模；
- 轻像素工业朋克、黑色幽默与正向成长，残疾遭遇不作为笑点。

## C. 必须先解决的冲突

1. **玩家表现**：旧原型是“鼠标就是鞋子、没有人体”，新概念提出完整主角与义肢。推荐先制作“鼠标工具光标 + 改造菜单中的人物”作为低成本兼容版本，试验后再决定是否做完整人物。
2. **场景与 UI**：当前 1280×720、左栏/大车库、略俯视；新设想一度提出右侧升级区、侧视角色、640×360。**现有布局优先**，不自动变更。
3. **供货与垃圾数量**：现有供罐连续、罐子永久堆积；新文字曾提议单个物品清空后补货/平台槽位。**持续供货优先**，如升级为多物品需保留玩家清理行为与可见积累。
4. **数值差异**：当前脚踩 0.68s、18 元首级 power；新方案草案 0.55s、30 元加固鞋。**旧数据优先**，仅在独立新平衡实验中调整。
5. **离线收益**：当前明确关闭；新方案仅作为未来可选功能。无确认不打开。

- 本次新增文档是第一版系统化提案，不能自动视为团队逐项批准所有参数。
- 改玩法前以 Issue 记录具体采用哪条方案；修改代码时同步测试、数据与存档迁移文档。
- 不依据过往聊天记忆覆盖 GitHub 中已认可的 v1.1 需求；版本化仓库为持续协作的权威记录。
- 重大设计选择按日期增量记录，不涂改历史事实；完成后在 docs/PROJECT_STATE.md 说明目前执行的是哪个版本。
